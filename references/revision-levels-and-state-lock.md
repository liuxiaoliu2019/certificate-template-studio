# 修改等级、修订历史与状态锁

## 1. 修改等级

### LEVEL1：轻改

适用：标题大小或颜色、人物小幅位移、元素缩放、局部装饰密度、留白大小、左右平衡、边缘弱连接、右下内侧减弱或最外沿收边等，不改变核心构图与设计语言。

处理：优先编辑当前图，锁定风格家族、全部 Profile 核心参数、主体、构图、主色、标题文字和人物身份，只改明确区域。

### LEVEL2：中改

适用：人物重新布局、标题区域重设计、边缘元素重新组织、安静区重塑、主次关系明显调整，但用户仍认可原方案的设计语言。

处理：以当前方案为基础生成变体；锁定风格家族、标题原文、中央功能区、人物身份和已认可的主要视觉语言，允许调整该家族内的密度、角色位置与连接方式。`frame_led` 的完整边框结构继续锁定。

### LEVEL3：重做

适用：“整套感觉不对”“不像证书”“换一个完全不同方向”等，或当前构图无局部修复价值。

处理：保留教材封面、Style DNA、角色身份档案、标题与对应控制模板，解除风格家族锁，重新评分或建立新的 Style Profile。人物身份锁不解除；旧 Profile 和构图必须保留。

若反馈同时包含多个层级，以最高影响层级为准，并向用户简短说明判断；不需要为了分类额外追问。

## 2. 修订记录不变量

- 每次输出使用新 revision id，不覆盖旧图片。
- 记录生成时间、方向、等级、来源文件、结果文件、用户反馈、SHA-256、风格家族、Profile 路径、变化参数与锁定参数。
- 回退只改变 active revision，不删除更晚版本。
- “回退后继续修改”以回退目标为 base，创建新的 revision 分支记录。

## 3. 横版状态机

```text
not_started -> exploring -> candidate_selected -> revising
                                  |                |
                                  +-------> awaiting_approval
                                                    |
                               用户明确批准 --------+
                                                    v
                                                 approved
```

`approved` 只能通过显式审批动作进入。生成完成、模型推荐、评分达标、选择方案或保存为候选都不能自动批准。

## 4. 明确批准与非批准

可视为批准的表达需同时满足“明确的定稿意图”与“对象明确”，例如：

- “横版定稿。”
- “确认横版定稿。”
- “确认方案 2 为横版定稿。”

不能视为批准：

- “继续”“下一步”“好的”“第一个可以”“这个不错”（对象或动作不明确或只有偏好）
- “方案 2 最好看”（偏好，不是定稿）
- “先选方案 2，再改一下标题”（仍需修改）
- 模型自己的推荐、评分或推断

若用户说“继续”而当前正等待横版确认，应继续停留在当前阶段并简短询问是要修改还是确认当前横版；不得擅自批准。

## 5. 竖版锁

- `landscape.status != approved` 时，`portrait.status` 必须为 `blocked`。
- 横版批准后，portrait 可变为 `ready` 或 `generating`。
- 横版批准后又发生实质修改时，应撤销旧批准并重新等待确认；已生成的竖版标记为 `stale`，不得继续当作当前 Master。
- 竖版也需用户明确表达“确认竖版定稿”；横版审批不向竖版传递。

## 6. 脚本使用

普通字段可用 `update_manifest.py --set` 更新，但脚本禁止用 `--set` 直接写 approval/status 锁字段。批准必须调用 `--approve-landscape` 或 `--approve-portrait` 并保存用户原话。

回退使用 `record_revision.py --rollback <revision_id>`，不删除任何文件。
